## 2. Verificação final

A verificação foi uma rodada única, feita num worktree com instalação própria e build de produção, depois que as quatro frentes terminaram. Cada frente só verificou a própria tela durante o trabalho.

| Verificação | Resultado |
| --- | --- |
| `npm run build` | passa |
| `npx tsc --noEmit` | 0 erros |
| Vitest | 218 testes passando (21 arquivos) |
| Suíte Playwright (`app/e2e`, doc 18): 5 personas × telas de cada uma × notebook, iPad paisagem, iPad retrato e iPad WebKit | **121 de 121** depois das correções abaixo (primeira rodada: 5 de 121) |

A suíte mede, em cada tela:

- título visível;
- nenhuma rolagem horizontal;
- nenhum erro de console;
- nenhuma violação séria ou crítica do axe;
- no toque, alvos de pelo menos 44 px e texto de pelo menos 13 px.

Ela anexa a captura de cada tela ao relatório (`npx playwright show-report e2e/.relatorio`).

**Correções da rodada** (commits `338f5e9` e `dd982fe`):

| Achado | Onde | Correção |
| --- | --- | --- |
| `label-content-name-mismatch` em todas as telas | botão "Trocar pessoa" do header | o nome acessível começa pelas iniciais visíveis |
| `label-content-name-mismatch` (8 por tela) | blocos de falha do MTBF | o nome é o texto do bloco, com a ação em texto só para leitor de tela |
| `aria-valid-attr-value` | abas usadas como filtro (Alertas, Painel, Notificações) | `aria-controls` aponta para a lista ou a tabela filtrada |
| `aria-valid-attr-value` | − e + do NumberField (Hora x Hora, Sobrepeso) | `id` na raiz do campo: os botões apontam para o input de verdade |
| `aria-valid-attr-value` (`aria-posinset="0"`) | stepper do checklist (Dice UI) | posição e total só quando conhecidos |
| `aria-allowed-attr` | timeline da Minha Rotina (Dice UI) | sem `aria-orientation` em `role="list"` |
| texto de 12 px no toque | "Abrir MTBF", "Ver tarefas dos postos", versões em Padrões | 14 px no toque |
| alvos de 18 px no toque | links dos eventos no Histórico | 44 px de altura no toque |
| aviso de console no WebKit | meta viewport `interactive-widget` | a chave fica (é ela que faz o Chrome do Android encolher a tela com o teclado); a suíte ignora esse aviso, documentado no teste |

**Fora da suíte**, a cobrir no piloto ou no aparelho:

- **Os fluxos de escrita.** A suíte abre as telas, mas não aponta, não encerra falha, não passa turno nem avança o relógio. As frentes C e D verificaram esses fluxos à mão; A e B não registraram capturas, porque o servidor de desenvolvimento estava instável (relatórios A §5 e B §4).
- **O modo escuro.** Os pares de contraste foram medidos por token (doc 19), mas não por tela.
- **iPad e Galaxy Tab de verdade, com luva.**

## 5. Ambiente durante a v0.5

O servidor de desenvolvimento compartilhado (porta 3100) ficou sem responder por longos períodos. A primeira causa foram quatro frentes capturando telas ao mesmo tempo. Depois, uma reinstalação de `node_modules` no meio do trabalho corrompeu o cache do Turbopack. A frente D destravou o servidor movendo o cache corrompido, sem apagar nada (relatório D §5).

A lição foi para o processo (doc 18): durante o trabalho, cada frente verifica só a própria tela, e a rodada completa roda uma vez no build de produção. Instalação de dependências só em worktree com `node_modules` próprio, nunca por link para o do projeto.
